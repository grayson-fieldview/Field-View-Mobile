---
name: Annotation wire contract quirks
description: Cross-client stroke wire-format facts reverse-engineered from the production web bundle (width units, circle geometry, arrowhead, text anchoring)
---

Facts confirmed by reading the deployed web client bundle (July 2026), since API endpoints are auth-gated:

- **Width units are ambiguous on the wire.** Web writes/reads raw display px (integer slider 1–8, default 3, `ctx.lineWidth = width` unscaled). Legacy mobile wrote 1000-virtual-canvas units (virtually always non-integer, e.g. 14.925 = 5px/335px canvas).
  **Rule:** id-provenance ladder, no value inspection (`widthToPx` in mobile services/annotations.ts): (1) local `size`/`canvasW` = authoritative px; (2) bare base-36 id (≤20 chars, [0-9a-z]+, at least one [g-z] — guaranteed by the leading timestamp char until 2059-05-25) = legacy mobile = 1000-units ALWAYS; (3) everything else = px (web UUID, web `s-` fallback, new mobile `fv-`+UUID ids from newStrokeId()); unrecognized shapes still read px but console.warn + Sentry breadcrumb (reporter injected via setUnclassifiedStrokeIdReporter so annotations.ts stays node-testable). Mobile never minted UUIDs historically (git-verified). Stored widths with ids are never rewritten; EXCEPTION: id-less strokes without canvas meta are definitively the 1000-unit era, so save normalizes their width to px BEFORE minting the `fv-` id (order: canvasMeta check first). Server schema (from web bundle): strict-strip plain z.union; width/id/color required, no points min-length, no coord clamping, fontSize clamped 8–96, text content min(1) — empty content 400s the ENTIRE row (text tool must never save empty). Legacy 1000-unit widths decode to the pen set {3,6,12} (git-sourced: pen-size UI never used any other array) — SNAP to nearest pen, never plain round (pen 6 on 430pt rounds to 5, snaps to 6). Backfill (scoped, NOT run) must rewrite width AND id in the same UPDATE — prefix the base-36 id with `fv-` — otherwise the ladder re-reads the converted px width as 1000-units and a re-run is repeatably destructive; the prefix makes it idempotent and preserves uniqueness/provenance. Client-side this is safe: loadPhotoAnnotations replaces cached rows wholesale (no union of local+server strokes by id), so no double-render; only risk is standard last-write-wins if a dirty local buffer flushes after the backfill.
- **Circle wire = `points: [center, radiusPoint]`** rendered as a perfect circle with r = px distance — NOT bounding-box ellipse, contradicting an earlier stated contract. Follow the web renderer.
- **Arrow head is derived, never stored:** length `max(12, widthPx*4)` px, half-angle π/6 off the shaft.
- **Text:** top-level normalized x/y (no points), fontSize raw px, canvas `textBaseline="top"` on web. Mobile SVG approximates with baseline offset ≈ 0.8·fontSize.
- Web internal type "freehand" serializes as wire "pencil". line/arrow/rectangle = `points:[start,end]`.
- **Why:** mobile↔web strokes were mutually mis-rendered/invisible; these conventions make them interoperate.
- **How to apply:** any change to mobile stroke converters/renderers must match these; re-verify against the current web bundle if behavior looks off.

Testing note: mobile has no test framework; `pnpm --filter @workspace/mobile test` runs `node --test` with native type stripping — requires explicit `.ts` extensions on relative imports in files the tests pull in (Metro resolves them fine; verified via bundle fetch), plus `allowImportingTsExtensions`+`noEmit` in mobile tsconfig.
