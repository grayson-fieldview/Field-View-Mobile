TIME SOURCE — going with Option (d), not (b):

Use the matched pendingExit's firesAt as the firedAt timestamp. Mobile already has this 
value from the exit-detected response, persisted in PendingExitRecord. The cron fires within 
~60 sec of firesAt being reached. So firedAt ≈ actual server clockOut time, within a minute.

Amendment to FiredExit interface:

  interface FiredExit {
    entry: BackendTimesheetEntry;  // pre-fire snapshot (clockOut is null by definition)
    firedAt: string;               // from matched pendingExit.firesAt
                                   // approximates actual server clockOut to within 60 sec
                                   // (cron polls every minute from when firesAt is reached)
  }

In the post-fact discovery block, when matched record is found:
  setFiredExit({ entry: prevActive, firedAt: matched.firesAt })

This avoids the API round-trip from option (a), avoids the "Just clocked out at 3:42 PM 
when actual was 3:00 PM" lie from option (b), and is precise enough for the conversational 
"Just clocked out at {time}" copy.

COLD-START GAP — needs fixing in 5a or follow-up:

Your current design works for live foreground transitions but misses the case where:
1. User auto-clocks-in
2. App killed
3. Server fires cron 5 min later
4. User cold-launches app
5. Initial refresh: prev=null (cold start), next=null (already clocked out)
6. Comparison fails: prev !== null is false
7. No firedExit surfaced. User sees clocked-out state with no banner / no Undo.

Fix proposal: persist last-seen-active to AsyncStorage on every refresh-success transition. 
On initial mount, restore lastSeenActive from storage as the seed for prevActive. Then 
comparison works on cold start.

  - lastSeenActive: { id, projectId, clockIn } — minimal shape, just enough for the 
    comparison + matching pendingExits lookup
  - storage key: @fv/last_seen_active_v1
  - written on every successful refresh after setActive
  - read once on initial mount, before the first refresh, and seeded into activeRef

Alternative: skip cold-start coverage entirely. The user just sees they're clocked out, 
they figure it out. They can manually re-clock-in if it was wrong. No undo path within the 
60-min window though.

(documented in code as known limitation, future S32a follow-up).
