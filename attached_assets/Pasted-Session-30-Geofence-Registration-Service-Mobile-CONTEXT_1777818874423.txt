PREREQUISITE — server endpoint must exist first

Before writing any mobile code, this session needs a new server endpoint. I'm working in Replit Web Agent in parallel to add it. The endpoint contract:

GET /api/projects/geofence-eligible
- Auth: same as other authenticated endpoints (requireAuth or equivalent)
- Returns: array of { id: number, name: string, latitude: number, longitude: number, lastActivityAt: string | ISO date }
- Filtering: project.accountId === currentUser.accountId AND project.archived === false AND project.latitude !== null AND project.longitude !== null AND lastActivityAt within last 14 days
- "lastActivityAt" = max(project.updatedAt, last clock-in by any user on project, last photo uploaded to project) — we'll need to compute this server-side
- Sort: lastActivityAt DESC
- Limit: 20 (hard cap matches iOS region cap)
- Restricted role: only includes projects assigned to the user, same logic as existing project list endpoint

Confirm with me before writing mobile code that this endpoint exists and matches the contract above. If it's not ready, stop and wait.

LOCKED DECISIONS FROM PHASE 2 SPEC

- Region strategy: Option B (recent-active only, last 14 days)
- Region cap: 20 (iOS hard limit)
- Radius: 30 meters per project (hardcoded for v1)
- Re-registration triggers: app launch (after auth), AppState change to "active", manual project list refresh
- Re-registration is idempotent: no thrash, no duplicate regions
- Permission gate: only registers regions when status === "always-granted"
- Logs to dev console for verification (will be cleaned up before paid marketing launch)

WHAT TO BUILD

1. New service: artifacts/mobile/services/geofencing.ts

Exports:
- registerGeofences(projects: GeofenceEligibleProject[]): Promise<RegistrationResult>
  - Diffs current registered regions against the input list
  - Unregisters regions no longer in the input
  - Registers new regions in the input not already registered
  - No-ops if a region's already registered with the same identifier
  - Returns { registered: string[], unregistered: string[], skipped: string[], errors: Array<{id, error}> }
- unregisterAllGeofences(): Promise<void>
  - Used when permission is revoked or user logs out
- getRegisteredGeofences(): Promise<string[]>
  - Returns list of currently-registered region identifiers (for debugging)

Internals:
- Uses expo-location's Location.startGeofencingAsync() with TaskManager
- Region identifier format: "fv-project-${projectId}" (stable, matches between registrations)
- Each region: { identifier, latitude, longitude, radius: 30, notifyOnEnter: true, notifyOnExit: true }
- Define a TaskManager task name: "fv-geofence-task" — but DO NOT implement the task body yet. Stub it with a console.log("[geofence] task fired:", eventType, region) so we can verify regions trigger correctly. Real handler comes in Session 31.

2. New hook: artifacts/mobile/hooks/useGeofenceSync.ts

- Pulls projects from the new GET /api/projects/geofence-eligible endpoint
- Calls registerGeofences() with the result whenever:
  - Hook mounts
  - AppState changes to "active"
  - useLocationPermission() status changes to "always-granted"
- Calls unregisterAllGeofences() whenever status changes AWAY from "always-granted"
- Exposes { syncing: boolean, lastSync: Date | null, registeredCount: number, error: Error | null } for debug surfacing
- Skips sync entirely if status !== "always-granted" (no-op, returns early)
- Skips sync if user is not authenticated

3. Integration into app

- Call useGeofenceSync() once at the (tabs) layout level — same level as the LocationPermissionBanner, since both are gated on tab navigation
- Do NOT call it in any onboarding/auth screens — only when user is actually in the main app

ACCEPTANCE CRITERIA

- On a fresh app launch with always-granted permission, console logs show: "[geofence] sync starting", "[geofence] registered N regions" where N is the count of recent-active projects with lat/lng (capped at 20)
- Permission revoked via Settings (Always → While Using App) → AppState refresh → console logs "[geofence] unregistering all regions" → all regions cleared
- Permission re-granted → console logs new sync → regions re-registered
- Same project appearing in two consecutive syncs is NOT re-registered (idempotency)
- Project archived in web manager dashboard → on next sync, that project's region is unregistered
- Project created with valid lat/lng → on next sync, registered
- Project created without lat/lng → never registered (server filter)
- Manual clock-in flow unaffected
- Banner / onboarding unaffected
- App startup time not visibly slower (sync is async, doesn't block render)
