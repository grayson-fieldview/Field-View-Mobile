Build the failure UX for the upload queue. Photos that are uploading or failed need visual indicators in the gallery, and the first failure of each session should trigger a toast notification.
Three pieces to build:

Per-photo status indicators in the gallery (PhotoTile component)
Toast notification when uploads fail
Tap-on-failed-photo action sheet with Retry / Remove options


Piece 1: Per-photo status indicators
Photos in the gallery should show a small visual indicator based on upload status. The upload status comes from the queue, not directly from the photo object — we need to map a local Photo to its queue item via uploadQueueId.
Status states and indicators:

uploading (queue item exists with status pending or uploading): show a small spinner/progress indicator in the bottom-right corner of the tile, with a translucent dark overlay at low opacity (~20%) on the photo so the user knows it's not finalized
failed (queue item exists with status failed): show a small red exclamation badge in the bottom-right corner. No overlay — photo is fully visible and tappable.
uploaded (no queue item, or queue item with uploaded status): show nothing. Photo renders normally.

Implementation:
a. Hook up the queue subscription — There's already a subscribe(...) function on services/uploadQueue. Find a sensible place to consume it. The cleanest approach is probably a new context or hook (useUploadStatus(queueId) returns "uploading" | "failed" | null) that subscribes once at the provider level and exposes per-photo status to consumers.
Recommended: create a new contexts/UploadStatusContext.tsx provider that:

Subscribes to the upload queue once on mount (via subscribe)
Maintains a Map<string, QueuedUpload> keyed by uploadQueueId
Exposes a useUploadStatus(uploadQueueId?: string) hook that returns the current QueuedUpload or null
Wrap the app inside the existing provider tree (likely in app/_layout.tsx, inside DataContext)

b. Modify PhotoTile — In app/project/[id].tsx, the PhotoTile component renders each photo. Update it to:

Receive the photo object as it already does
Internally call useUploadStatus(photo.uploadQueueId) to get queue state
Render the appropriate visual indicator based on status
Apply the translucent overlay only when uploading

Use existing icons from lucide-react-native if available, otherwise plain SVG or text glyphs (✓ for nothing, ⏳ for uploading, ! for failed).

Piece 2: Toast notification on first failure of session
When the upload queue marks an item as failed for the first time in this app session, show a toast that says: "Some photos failed to upload — they'll retry automatically."
Behavior:

Show only ONCE per app session, regardless of how many failures occur after that
Toast disappears after 4 seconds
User can tap the toast to dismiss early
Toast does NOT appear again if more photos fail later in the same session
Counter resets on app relaunch

Implementation:
a. Use a simple toast library if one is already in the project. Check package.json for react-native-toast-message, react-native-root-toast, expo-notifications, or similar. If none exists, build a minimal in-app toast component (a fixed-position View at top of screen, fades in/out).
b. The trigger logic lives in the same place as the queue subscription (the new UploadStatusContext). Track a hasShownFailureToastThisSession boolean. When subscribing to queue updates:

On every queue change, check if any item with status failed was previously not in failed state
If yes AND the session toast hasn't been shown: show toast, set hasShownFailureToastThisSession = true

c. The toast text should be neutral ("they'll retry automatically") not alarming ("UPLOAD FAILED"). Field workers don't need stress; they need information.

Piece 3: Tap-on-failed-photo action sheet
When a user taps a photo that's in failed status, show an iOS-native action sheet with two options: "Retry now" and "Remove from queue". Plus a Cancel option.
Behavior:

Tap on uploading photo → no action sheet, opens the photo detail screen normally (or does nothing — designer's choice; default to opening the detail)
Tap on failed photo → action sheet appears

"Retry now" → calls retryItem(uploadQueueId), action sheet dismisses
"Remove from queue" → calls removeItem(uploadQueueId) AND removes the local photo from state. Confirms with user first ("Remove this photo? It hasn't been uploaded yet and will be lost.")
"Cancel" → just dismisses


Tap on uploaded photo → opens photo detail screen normally

Implementation:
a. Use ActionSheetIOS from React Native for iOS. For Android, use Alert.alert with the same options as a fallback.
b. The "Remove from queue" path needs to also remove the local Photo from DataContext so it disappears from the gallery. Add a method to DataContext like removePhoto(photoId: string) if one doesn't exist.
c. Wire this up inside PhotoTile's onOpen handler — branch based on upload status before deciding whether to open detail or show action sheet.

What NOT to do:

Don't add upload progress percentages (e.g., "47% uploaded") — the queue doesn't track per-byte progress and adding that is significant scope
Don't add a "View all failed uploads" screen — failure indicators are per-photo, no separate screen needed
Don't add notifications via expo-notifications (push notifications) — this is in-app toast only
Don't add background task registration for uploads while app is closed — separate iteration
Don't change the queue's retry logic — it's already correct
