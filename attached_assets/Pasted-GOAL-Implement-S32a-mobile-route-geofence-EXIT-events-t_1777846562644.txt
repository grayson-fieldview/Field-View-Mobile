GOAL
Implement S32a-mobile: route geofence EXIT events through the new server-side debounce infrastructure shipped tonight (S32a-web).

S32a-web is already live in production:
- POST /api/geofence/exit-detected (idempotent, returns {id, firesAt, status})
- POST /api/geofence/exit-cancelled (cancels a pending row by pendingExitId or timeEntryId)
- GET /api/cron/process-pending-exits (server fires the auto clock-out 5 min after exit)
- DELETE /api/timesheets/:id/auto-undo extended to handle re-opening recently auto-clocked-out entries

Mobile's job:
1. When OS fires a geofence Exit event for a registered project (and user is currently auto-clocked-into that project), POST to /api/geofence/exit-detected. Persist the returned {pendingExitId, timeEntryId} pair locally.
2. If the user re-enters the SAME geofence within 5 minutes (i.e., before server fires), POST to /api/geofence/exit-cancelled with the persisted pendingExitId.
3. After the server fires (next time the app foregrounds and polls /api/timesheets/active and finds the entry's clock_out is now populated), surface a post-facto receipt banner with Undo. Same UX pattern as the existing clock-IN receipt banner from S31b.

=== PART 2: NEW FUNCTION handleGeofenceExit ===

Place inside services/geofencing.ts (not exported except via GEOFENCE_INTERNALS for testing).async function handleGeofenceExit(
regionId: string,
// Optional Location event payload if available — used for GPS uncertainty filtering
// and proximity check. Pass null/undefined if the OS event doesn't carry location.
location?: { latitude: number; longitude: number; accuracy?: number | null },
): Promise<void>

LOGIC:

A. Parse projectId from regionId via parseProjectId. If null → log "exit for unknown region" and return.

B. Filter chain — different from enter's. Apply in order, cheapest first:

   B1. **GPS uncertainty filter (cheapest, optional)**: if location.accuracy is provided AND > GPS_ACCURACY_THRESHOLD_M → log and return. Same threshold as enter.
   
   B2. **Active session check**: call api.getActiveTimeEntry() (or whatever the existing method is — find it in services/api.ts). If no active session → log "no active session, ignoring exit" and return.
   
   B3. **Active session matches this project**: if active.projectId !== projectId → log "exit for different project than active" and return. (User clocked into Project A, geofence for Project B fires Exit — ignore. Common scenario when projects are spatially close.)
   
   B4. **Active session source check**: if active.source !== "auto_geofence" → log "active session is manual, refusing to auto-exit" and return. CRITICAL: never auto-clock-out manual sessions. User explicitly clocked in manually, their decision to clock out is also manual.
   
   B5. **Already-pending-exit check**: query local pending exit storage (Part 4) for this timeEntryId. If a pending row already exists → log "exit already pending, idempotent skip" and return. The server is also idempotent on this, so duplicate calls are safe, but we save the network round-trip.

C. POST to /api/geofence/exit-detected with {projectId, timeEntryId: active.id, detectedAt: new Date().toISOString()}. Wrap in try/catch.

D. On success (returns {id, firesAt, status}):
   - Persist {pendingExitId: response.id, timeEntryId: active.id, projectId, regionId, firesAt} to AsyncStorage (Part 4).
   - Schedule a local watchdog timeout: setTimeout for (firesAt - now + 60 seconds buffer). When it fires, call refreshActiveTimeEntryAndShowReceiptIfClockedOut() (Part 5). This is fallback; the primary discovery path is foreground polling.
   - Log success.

E. On failure (network error, 4xx, 5xx):
   - DO NOT silently swallow. Log to Sentry.
   - DO NOT retry inline (TaskManager runs are short; retries amplify load).
   - Persist a "pending unsent exit" marker so that on next app foreground, we re-attempt the POST. (See Part 4 schema.)

=== PART 3: ENTER → MAYBE-CANCEL ===

In runGeofenceTaskBody Enter branch (existing), AFTER the existing "already clocked in to this region recently" debounce check passes and BEFORE doing the actual clock-in API call:

Check pending exit storage (Part 4) for this regionId. If a pending exit exists for this region:
- POST /api/geofence/exit-cancelled with {pendingExitId} from the stored row.
- On success → remove the local pending exit record. Skip the new clock-in (user is still in the same session, debounce-cancelled).
- On failure → log + Sentry, but proceed with new clock-in attempt anyway (the server's idempotency on exit-detected won't help us here, but server cron will fail-safely if the user was never clocked out).

This is the "user briefly stepped outside, came back" path. Net effect: no DB churn, session continues uninterrupted.
